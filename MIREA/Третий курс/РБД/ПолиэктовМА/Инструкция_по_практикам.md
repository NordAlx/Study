INNER JOIN показывает клиентов с сеансами. LEFT JOIN сохраняет всех клиентов; COUNT(id_rental_session) возвращает ноль при отсутствии посещений. Цена тарифа определяет бюджетную, стандартную, расширенную либо премиальную категорию. Используются три WHEN и ELSE. CASE внутри SUM отдельно считает дорогие и недорогие сеансы каждого клиента.

### Ранжирование

RANK распределяет сеансы каждого сотрудника по убыванию стоимости. Внешний запрос оставляет первые три ранга. При одинаковых суммах на границе допустимо несколько строк с одинаковым рангом.

### Нарастающий итог

Сначала стоимость группируется по тарифу и месяцу документа. SUM OVER с PARTITION BY id_tarif и рамкой ROWS рассчитывает накопленную сумму до текущего месяца.

### Сравнение месяцев LAG

Календарь сохраняет все месяцы 2025 года, даже без сеансов. Пропущенная сумма заменяется нулём. LAG возвращает показатель предыдущего календарного месяца; первая строка без предыдущего периода исключается.

### Два варианта сводки

Строки соответствуют сотрудникам, столбцы — четырём кварталам 2025 года. SUM и CASE и crosstab используют одинаковые границы года и сохраняют сотрудников с нулевыми суммами. Для crosstab предварительно подключается tablefunc.

### Модифицируемое представление

v_paid_payments основано на одной payment без группировки. WITH LOCAL CHECK OPTION требует, чтобы запись, добавляемая через представление, сохраняла статус успешной оплаты. INSERT и DELETE показывают изменения базовой таблицы.

### Аналитическое представление

v_employee_revenue соединяет сотрудников и сеансы, вычисляет COUNT, SUM и AVG с GROUP BY. Оно автоматически немодифицируемо. Q04 отбирает сотрудников со средней стоимостью сеанса выше 700 рублей.

### Материализованное представление

mv_client_spending хранит рассчитанную стоимость сеансов клиента. Изменение источника не обновляет снимок автоматически. Демонстрация сравнивает исходный снимок, текущее значение источника и результат после REFRESH; затем учебное изменение откатывается.

### Скалярная функция

employee_revenue принимает ID сотрудника и возвращает сумму успешных оплат завершённых сеансов. Внутри соединяются rental_session и payment. Вызов функции включается в SELECT по сотрудникам.

### Процедура и два вызова

spend_bonus проверяет число баллов и существование карты, блокирует её FOR UPDATE, уменьшает points и регистрирует списание. При недостаточном балансе возвращает статус ошибки через OUT без изменений. Успешный и неудачный вызовы выполняются в учебной транзакции с ROLLBACK.

Для карты 1 нужно минимум 50 баллов. Последний NULL в CALL соответствует параметру OUT.

### Контроль оплаты сеанса

BEFORE INSERT OR UPDATE получает и блокирует связанную оплату. Завершённый сеанс допускается только при успешном статусе и достаточной сумме. Иначе RAISE EXCEPTION прерывает изменение.

### Аудит и согласованность

AFTER UPDATE сохраняет OLD и NEW для суммы и статуса, дату и пользователя. Изменение, нарушающее оплату уже завершённого сеанса, вызывает исключение, отменяющее весь UPDATE.

### Защита финансовой истории

BEFORE DELETE запрещает удалять успешную оплату даже без ссылок на неё. Неподтверждённый платеж без связей удалить можно. Этот бизнес-запрет не сводится к внешнему ключу.

### Два курсора

Явный курсор использует OPEN, FETCH и CLOSE и выводит карты через RAISE NOTICE. Неявный FOR IN проходит статистику сотрудников в employee_activity и добавляет строки результата RETURN NEXT.

Для NOTICE включить журнал вывода сервера. Ошибочные примеры выполнять по операторам с отдельным ROLLBACK после отказа.

### Подготовка данных

Цикл PL/pgSQL добавляет ровно 20 000 оплат с существующими ссылками. Маркер generation_runs защищает от повторной генерации. ANALYZE обновляет статистику оптимизатора.

Генератор увеличивает payment; запускать самостоятельно на учебной копии базы.

### Три сценария индексов

B-Tree обслуживает поиск по сумме; индекс по выражению — фильтр LOWER(status); частичный — только успешные оплаты. Условия ДО и ПОСЛЕ каждого сценария идентичны. Фиксируются фактические узлы, Execution Time и Buffers.

Запускать блоками, сохраняя план ДО до создания индекса. Проверить существующие индексы. Не отключать enable_seqscan и не менять условия только для получения желаемого результата.

### Атомарность COMMIT

В одной транзакции блокируется карта, проверяется баланс, уменьшаются points и добавляется запись bonus_redemption. COMMIT фиксирует обе связанные операции.

Нужна bonus_redemption из практики 5 и карта 1 с минимум 50 баллами.

### Откат ROLLBACK

После уменьшения баланса заведомо отрицательное списание нарушает CHECK. ROLLBACK отменяет изменения баланса и истории. Значения последовательностей ID при откате могут не возвращаться.

Выполнять по операторам. После ошибки отдельно выполнить ROLLBACK.

### Неповторяемое чтение

A открывает READ COMMITTED и читает баланс. B увеличивает его и выполняет COMMIT. Второй SELECT в A видит новое значение, поскольку каждый оператор получает свежий снимок.

Нужны два разных подключения с различными pg_backend_pid. Порядок: BEGIN A и первый SELECT; весь B; второй SELECT A; COMMIT A.

### Устойчивый снимок

При REPEATABLE READ второй SELECT A после COMMIT B возвращает прежнее значение. Новое становится видимым после завершения A. Этот уровень не запрещает другим пользователям менять данные.

Повторить порядок двух подключений. Не запускать A целиком, иначе вмешательство B не попадёт между чтениями.
