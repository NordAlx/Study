# BPMN 2.0 — справочник элементов и правил

Разобраны все 75 карточек основного каталога StormBPMN и дополнительная карточка Manual Task, найденная в связанных элементах. Названия ниже позволяют найти символ на сайте; описание исправляет неточности и указывает применение в выбранной учебной модели. Это не требование использовать все символы в одной схеме.

Источники: [каталог StormBPMN](https://stormbpmn.com/elements) и [стандарт OMG BPMN 2.0.2](https://www.omg.org/spec/BPMN/2.0.2/PDF). Для каждого элемента приведена прямая ссылка на его карточку.

## Общие правила событий

Начало — один тонкий круг; промежуточное событие — двойной; конец — толстый. Catch ожидает наступления события и обычно имеет незаполненный маркер; Throw инициирует событие и имеет заполненный маркер. Таймер и условие только ловят соответствующий триггер. У прикреплённого события нет входящего Sequence Flow: оно активируется вместе с содержащей деятельностью. Его исходящая ветвь должна вести к обработке.

Прерывающее граничное событие имеет сплошную окружность и прекращает выполняемую деятельность; непрерывающее — пунктирную и создаёт дополнительную ветвь. Эти понятия относятся к текущей области, а не автоматически ко всей кампании. Для компенсации этот признак неприменим: компенсируется уже завершённая деятельность.

У обычного встроенного подпроцесса старт без специального триггера. Специальные прерывающие/непрерывающие Start предназначены для событийных подпроцессов. Ошибку и эскалацию не получать межпуловым Message Flow; это разные механизмы взаимодействия.

## Карточки элементов

### 1. Группа

[Карточка StormBPMN](https://stormbpmn.com/elements/group). Визуальная группировка с общей категорией; не задаёт порядок работ и не заменяет пул или дорожку.

**В нашей модели:** Не требуется; ответственность показывают дорожки.

### 2. Компенсирующее действие

[Карточка StormBPMN](https://stormbpmn.com/elements/compensation-activity). Обрабатывает компенсацию уже завершённой деятельности; помечена как компенсационная и подключается к обработчику ассоциацией.

**В нашей модели:** Нет; исправление медиаплана — обычная доработка.

### 3. Выполнение бизнес-правила (Задача-выполнение бизнес-правила)

[Карточка StormBPMN](https://stormbpmn.com/elements/business-rule-task). Передаёт данные механизму бизнес-правил и получает результат; не обозначает человеческую проверку правил.

**В нашей модели:** Нет; директор проверяет документы сам.

### 4. Получение сообщения (Задача-получение сообщения)

[Карточка StormBPMN](https://stormbpmn.com/elements/receive-task). Ожидает сообщение другого участника; после получения завершается. Почтовый канал сам по себе не запрещает этот тип.

**В нашей модели:** Отдельно не нужен: получение и проверка включены в задачи сбора.

### 5. Выполнение сценария (Задача-выполнение сценария)

[Карточка StormBPMN](https://stormbpmn.com/elements/script-task). Исполняется процессным движком как сценарий; не обозначает ручную работу в приложении.

**В нашей модели:** Нет; такое выполнение не установлено.

### 6. Отправка сообщения (Задача-отправка сообщения)

[Карточка StormBPMN](https://stormbpmn.com/elements/send-task). Специализированная отправка сообщения другому участнику; после отправки задача завершена. Для внутреннего письма маркер не нужен.

**В нашей модели:** В выбранной детализации ручная отправка входит в обычные задачи.

### 7. Дорожка

[Карточка StormBPMN](https://stormbpmn.com/elements/lane). Распределяет действия внутри участника; поток управления может пересекать границы дорожек. Рекомендация сайта отказаться от дорожек не является запретом.

**В нашей модели:** Да; полные названия шести основных ролей.

### 8. Начальное прерывающее событие-компенсация

[Карточка StormBPMN](https://stormbpmn.com/elements/start-interrupting-compensation-event). Начало обработчика компенсации внутри соответствующего событийного подпроцесса; не старт верхнего процесса. Компенсация обращается к завершённой работе.

**В нашей модели:** Нет; прерывающий смысл подписи сайта нельзя переносить на выполняемую задачу.

### 9. Промежуточное прикрепленное прерывающее событие-обработчик компенсации

[Карточка StormBPMN](https://stormbpmn.com/elements/intermediate-attached-interrupting-compensation-catch-event). Граничный обработчик вызывается для компенсации завершённой задачи; связывается с компенсирующим действием ассоциацией, а не обычным Sequence Flow. Не прерывает эту уже завершённую задачу.

**В нашей модели:** Нет; название «прерывающее» на сайте неточно.

### 10. Конечное событие-инициатор компенсации

[Карточка StormBPMN](https://stormbpmn.com/elements/end-compensation-throw-event). Завершает текущий путь с запросом компенсации в установленной области; нужен определённый обработчик завершённых действий.

**В нашей модели:** Нет.

### 11. Промежуточное событие-инициатор компенсации

[Карточка StormBPMN](https://stormbpmn.com/elements/intermediate-compensation-throw-event). Запрашивает компенсацию в ходе маршрута; область и компенсируемые действия должны быть определены.

**В нашей модели:** Нет.

### 12. Конечное событие-останов

[Карточка StormBPMN](https://stormbpmn.com/elements/end-terminate-throw-event). Немедленно прекращает активность текущей области, включая оставшиеся её ветви; не подменяет любой отрицательный исход.

**В нашей модели:** Нет; отказ происходит до параллельного запуска.

### 13. Промежуточное прикрепленное прерывающее событие-обработчик отмены

[Карточка StormBPMN](https://stormbpmn.com/elements/intermediate-attached-interrupting-cancel-catch-event). Прикрепляется только к транзакционному подпроцессу и обрабатывает его отмену с предусмотренной компенсацией.

**В нашей модели:** Нет; отказ или замечания не являются Cancel.

### 14. Конечное событие-инициатор отмены

[Карточка StormBPMN](https://stormbpmn.com/elements/end-cancel-throw-event). Допустимо внутри транзакционного подпроцесса; инициирует его отмену.

**В нашей модели:** Нет.

### 15. Начальное прерывающее событие-ошибка

[Карточка StormBPMN](https://stormbpmn.com/elements/start-interrupting-error-event). Начало событийного подпроцесса-обработчика ошибки; всегда прерывает содержащую область, не является самостоятельным стартом кампании.

**В нашей модели:** Нет; бизнес-замечания маршрутизируются XOR.

### 16. Промежуточное прикрепленное событие-обработчик ошибки

[Карточка StormBPMN](https://stormbpmn.com/elements/intermediate-attached-interrupting-error-catch-event). Ловит ошибку выполняемой деятельности на её границе, прерывает её и запускает обработку; непрерывающего варианта нет.

**В нашей модели:** Нет.

### 17. Конечное событие-инициатор ошибки

[Карточка StormBPMN](https://stormbpmn.com/elements/end-error-throw-event). Завершает текущий путь и выбрасывает ошибку для соответствующего обработчика/области; не заменяет обычный отрицательный ответ.

**В нашей модели:** Нет.

### 18. Цикл по объектам

[Карточка StormBPMN](https://stormbpmn.com/elements/multi-instance-loop). Повторяет деятельность по коллекции объектов; указать коллекцию и параллельное либо последовательное выполнение.

**В нашей модели:** Не нужен при агрегированном сборе ответов магазинов.

### 19. Стандартный цикл

[Карточка StormBPMN](https://stormbpmn.com/elements/standard-loop). Повторяет одну деятельность по условию завершения; отличается от обработки коллекции.

**В нашей модели:** Не нужен: возвраты и проверки уже раскрыты шлюзами.

### 20. Подпроцесс по событию

[Карточка StormBPMN](https://stormbpmn.com/elements/event-subprocess). Обработчик внутри активной области, запускаемый собственным событием; пунктирная рамка, нет входящих/исходящих Sequence Flow к рамке.

**В нашей модели:** Не нужен для четырёх обычных этапов.

### 21. Подпроцесс «по требованию»

[Карточка StormBPMN](https://stormbpmn.com/elements/ad-hoc-subprocess). Набор действий без полностью заданного общего порядка; отдельные зависимости разрешены. Запрет сайта является рекомендацией.

**В нашей модели:** Не нужен: порядок работ определён.

### 22. Транзакционный подпроцесс

[Карточка StormBPMN](https://stormbpmn.com/elements/transactional-subprocess). Транзакционная область с согласованным завершением и специальной обработкой отмены; двойная рамка.

**В нашей модели:** Нет; кампания не объявлена транзакцией.

### 23. Вызов повторно-используемого действия

[Карточка StormBPMN](https://stormbpmn.com/elements/call-activity). Вызывает отдельно определённый глобальный процесс/задачу; толстая рамка. Не требуется только из-за отдельной страницы детализации.

**В нашей модели:** Нет; A1–A4 — обычные встроенные подпроцессы.

### 24. Ассоциативная связь

[Карточка StormBPMN](https://stormbpmn.com/elements/association-flow). Общая ассоциация связывает пояснения; для чтения и записи информации используется направленная Data Association. Управление не передаётся.

**В нашей модели:** Пояснения и привязка документов с уточнением типа связи.

### 25. Поток сообщений

[Карточка StormBPMN](https://stormbpmn.com/elements/message-flow). Передача между разными участниками; не используется между дорожками одного пула. Сообщение может содержать документ.

**В нашей модели:** Запросы, ответы, материалы и отчёт смежным участникам.

### 26. Поток управления

[Карточка StormBPMN](https://stormbpmn.com/elements/sequence-flow). Порядок выполнения внутри одного уровня одного процесса; не пересекает границы пула или подпроцесса.

**В нашей модели:** Основной маршрут и циклы доработки.

### 27. Комментарий

[Карточка StormBPMN](https://stormbpmn.com/elements/annotation). Пояснение, связанное ассоциацией с элементом; не является шагом исполнения.

**В нашей модели:** Для отдельных средств труда и границ задач.

### 28. Скрытый пул (Пул-«черный ящик»)

[Карточка StormBPMN](https://stormbpmn.com/elements/black-box-pool). Участник без раскрытия внутреннего процесса; сообщения могут соединяться с его границей. Раскрывать известные внутренности необязательно.

**В нашей модели:** Коммерческий блок и магазины.

### 29. Раскрытый пул

[Карточка StormBPMN](https://stormbpmn.com/elements/pool). Обозначает участника взаимодействия с показанным процессом; внутренняя работа соединяется Sequence Flow.

**В нашей модели:** Основной пул маркетинга.

### 30. Развилка «и» (Параллельная развилка)

[Карточка StormBPMN](https://stormbpmn.com/elements/parallel-gateway). Разделение создаёт все ветви без условий; объединение ждёт все входящие потоки.

**В нашей модели:** Подготовка и запуск двух направлений, сбор двух наборов показателей.

### 31. Комплексная развилка

[Карточка StormBPMN](https://stormbpmn.com/elements/complex-gateway). Требует явного правила активации/синхронизации, например заданного сочетания нескольких ответов.

**В нашей модели:** Не нужен для обычных Да/Нет или двух каналов.

### 32. Развилка по событиям

[Карточка StormBPMN](https://stormbpmn.com/elements/event-gateway). Событийный выбор ожидает альтернативные события; в обычном эксклюзивном варианте продолжает первый наступивший исход. Следом — допустимые catch-события или Receive Task, а не произвольная задача проверки.

**В нашей модели:** Не нужен: выбранные проверки основаны на уже полученных данных.

### 33. Развилка «или/или»

[Карточка StormBPMN](https://stormbpmn.com/elements/exclusive-gateway). Выбирает одну ветвь по данным; объединение альтернатив не синхронизирует потоки. Условия должны быть понятными и взаимоисключающими.

**В нашей модели:** Отказ, полнота данных, согласование, состав доработки.

### 34. Развилка «и/или»

[Карточка StormBPMN](https://stormbpmn.com/elements/inclusive-gateway). Разделение выбирает одну или несколько ветвей по условиям; объединение учитывает активированные ветви.

**В нашей модели:** Цифровая и/или розничная корректировка.

### 35. Начальное непрерывающее событие-сигнал

[Карточка StormBPMN](https://stormbpmn.com/elements/start-non-interrupting-signal-event). Запускает событийный подпроцесс при наступлении широковещательного сигнала; содержащая область продолжает работу. Сигнал не адресуется определённому экземпляру как письмо; отказ сайта от сигналов не является запретом.

**В нашей модели:** Не требуется в принятом сценарии.

### 36. Промежуточное прерывающее прикрепленное событие-обработчик сигнала

[Карточка StormBPMN](https://stormbpmn.com/elements/intermediate-attached-signal-catch-event). На границе выполняемой деятельности ожидает наступления широковещательного сигнала; прерывает деятельность и направляет работу по обработчику. Сигнал не адресуется определённому экземпляру как письмо; отказ сайта от сигналов не является запретом.

**В нашей модели:** Не требуется в принятом сценарии.

### 37. Начальное событие-сигнал

[Карточка StormBPMN](https://stormbpmn.com/elements/start-signal-event). Начинает процесс при наступлении широковещательного сигнала. Сигнал не адресуется определённому экземпляру как письмо; отказ сайта от сигналов не является запретом.

**В нашей модели:** Не требуется в принятом сценарии.

### 38. Начальное прерывающее событие-сигнал

[Карточка StormBPMN](https://stormbpmn.com/elements/start-interrupting-signal-event). Запускает событийный подпроцесс при наступлении широковещательного сигнала и прерывает содержащую область. Сигнал не адресуется определённому экземпляру как письмо; отказ сайта от сигналов не является запретом.

**В нашей модели:** Не требуется в принятом сценарии.

### 39. Промежуточное событие-обработчик сигнала

[Карточка StormBPMN](https://stormbpmn.com/elements/intermediate-signal-catch-event). В ходе маршрута ожидает наступления широковещательного сигнала; после него продолжает поток. Сигнал не адресуется определённому экземпляру как письмо; отказ сайта от сигналов не является запретом.

**В нашей модели:** Не требуется в принятом сценарии.

### 40. Промежуточное прикрепленное непрерывающее событие-обработчик сигнала

[Карточка StormBPMN](https://stormbpmn.com/elements/intermediate-attached-non-interrputing-signal-catch-event). На границе выполняемой деятельности ожидает наступления широковещательного сигнала; создаёт дополнительную ветвь без отмены деятельности. Сигнал не адресуется определённому экземпляру как письмо; отказ сайта от сигналов не является запретом.

**В нашей модели:** Не требуется в принятом сценарии.

### 41. Промежуточное событие-инициатор сигнала

[Карточка StormBPMN](https://stormbpmn.com/elements/intermediate-signal-throw-event). В ходе маршрута инициирует широковещательного сигнала и затем продолжает поток. Сигнал не адресуется определённому экземпляру как письмо; отказ сайта от сигналов не является запретом.

**В нашей модели:** Не требуется в принятом сценарии.

### 42. Конечное событие-инициатор сигнала

[Карточка StormBPMN](https://stormbpmn.com/elements/end-signal-throw-event). Завершает текущий путь и инициирует широковещательного сигнала. Сигнал не адресуется определённому экземпляру как письмо; отказ сайта от сигналов не является запретом.

**В нашей модели:** Не требуется в принятом сценарии.

### 43. Простое конечное событие

[Карточка StormBPMN](https://stormbpmn.com/elements/none-end-event). Завершает данный путь без специального результата-триггера; исходящего Sequence Flow нет. Другие активные пути само по себе не прекращает.

**В нашей модели:** Отказ, передача отчёта и результаты подпроцессов.

### 44. Простое начальное событие

[Карточка StormBPMN](https://stormbpmn.com/elements/none-start-event). Начало без формально заданного триггера; входящего Sequence Flow нет. Если запуск строго определяется сообщением или датой, нужен соответствующий тип.

**В нашей модели:** Начало кампании и входы в обычные подпроцессы.

### 45. Простое промежуточное событие-обработчик

[Карточка StormBPMN](https://stormbpmn.com/elements/none-catch-event). На сайте названо обработчиком; по OMG простое промежуточное событие без триггера является throw, фиксирующим состояние. Для ожидания нужен определённый триггер.

**В нашей модели:** Не требуется между каждой парой задач.

### 46. Промежуточное прикрепленное прерывающее событие-обработчик сообщения

[Карточка StormBPMN](https://stormbpmn.com/elements/intermediate-attached-interrupting-message-catch-event). На границе выполняемой деятельности ожидает наступления адресного сообщения участника; прерывает деятельность и направляет работу по обработчику. Отправитель и получатель — разные участники; содержимым могут быть данные документа.

**В нашей модели:** Не требуется в принятом сценарии.

### 47. Конечное событие-инициатор сообщения

[Карточка StormBPMN](https://stormbpmn.com/elements/end-message-throw-event). Завершает текущий путь и инициирует адресного сообщения участника. Отправитель и получатель — разные участники; содержимым могут быть данные документа.

## Элементы, которые также нужны для полной легенды

В основном каталоге сайта некоторые базовые символы не представлены отдельными карточками. Для построения дополнительно различать следующие типы.

| Тип | Значение | Применение |
|---|---|---|
| Task без маркера | Тип работы специально не уточняется | Все действия сотрудников в нашей инструкции |
| User Task | Человек выполняет задание, жизненным циклом которого управляет программный компонент | Не вводить только из-за использования Excel или компьютера |
| Service Task | Работу выполняет сервис или приложение | В as is автоматические интеграции не установлены |
| Обычный SubProcess | Составная работа с внутренним процессом; + у свёрнутого вида | SP1–SP4; раскрытие на отдельных листах |
| Data Association | Чтение/запись данных, отличающиеся от общей Association | Документы и постоянные хранилища |
| Message | Содержание межпулового обмена; значок конверта при необходимости | Можно оставить только подпись Message Flow |
| Default Flow | Путь, выбираемый при невыполнении остальных условий; косая черта у начала | При необходимости для полного покрытия XOR/OR |

## Уточнения к формулировкам сайта

- Дорожки, сигналы, ссылки и ad hoc являются элементами BPMN. Рекомендации автора избегать их не отменяют стандарт; в нашей модели дорожки нужны, остальные перечисленные элементы не требуются по сценарию.
- Свёрнутый пул можно использовать при сознательном исключении внутренних операций из детализации, даже если их общий смысл известен.
- Сообщение допускает передачу документа между участниками. Ограничение относится к границам участников, а не к формату email/SMS/вложения.
- Область доступности Data Object не означает физическое исчезновение реального документа. Хранение между экземплярами процесса показывается Data Store.
- Компенсационный обработчик работает для завершённых действий; обычная доработка материалов компенсацией не является. Из граничного компенсационного события к компенсационному действию проводится ассоциация.
- Простое промежуточное событие без триггера фиксирует состояние как Throw. Называть его ожидающим Catch и использовать вместо таймера или получения сообщения неправильно.
- Подготовка обеих ветвей перед запуском — решение для согласованной модели кампании; сам стандарт BPMN не требует, чтобы любые рекламные каналы всегда запускались одновременно.
